# ITL-994 + ITL-997: running a job in a notebook, and reporting failed rows

> **For agentic workers:** REQUIRED SUB-SKILL: Use sensei:executing-plans to implement this
> plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `PipelineJob.run` works with the async orchestrator inside a running event loop
(Jupyter), and after every run the user sees which rows failed, in which node, and why.

**Architecture:** ITL-994: `AsyncPipelineOrchestrator.run` runs its coroutine on a bridge
thread with its own loop when the caller's thread already runs a loop; `PipelineJob.run_async`
awaits the orchestrator's `run_async` for async code. ITL-997: `job.run` wraps the user's
observer with a private counting observer and returns a `RunSummary` built from its counts;
a `RowFailuresWarning` is issued when any row failed; `job.last_run` keeps the summary.

**Tech stack:** asyncio, threading, warnings; existing `CompositeObserver`.

**Branch:** `eywalker/itl-994-a-pipelinejob-cannot-be-run-with-the-async` from origin/main
(290889e8). One PR: Fixes ITL-994, Fixes ITL-997; one commit per issue; one changelog
fragment per issue.

## Findings (today, main 290889e8)

- `AsyncPipelineOrchestrator.run` = `asyncio.run(self._run_async(...))` -> RuntimeError in
  any running loop. `run_async` exists on the orchestrator, not on the job.
- `job.run()` returns `self`; ~38 test sites use the return value; no src callers.
- Sync: per-row `logger.warning(..., exc_info=True)` (function_node.py ~1763) prints one full
  traceback per failed row. Async: `logger.debug` (function_pod.py ~619): nothing shown.
- Observer per function-node row, both orchestrators: `on_data_end(cached=True)` (from the
  store), `on_data_end(cached=False)` (computed; output None = filtered), `on_data_crash`
  (with the exception object).
