## Decisions (coordinator, November 12, 2026, ask 1)

1. Deferred registration lives in `src/orcapod/contexts/logical_types.json`:
   `deferred_logical_types` in the `logical_type_registry` `_config`, and a new top-level
   `deferred_value_handlers`, read by `contexts/registry.py` through
   `PythonTypeHandlerRegistry.register_deferred(python_type, handler)`. `v1.json` is untouched.
   Keep the test that `torch` is absent from `sys.modules` after `import orcapod` and after
   building `std:v1:default`.
2. Function outputs follow `main`'s rule: a returned value is an instance of the declared class
   or of a subclass. The PR's relaxation (a plain base class for a declared unregistered
   subclass) is dropped for ndarray and tensor. PR #299 replaces the helper
   (`_check_declared_array_outputs`); whichever merges second deletes it.
3. Hash: unchanged. A tensor and an equal ndarray share the digest (`array_digest_v1`) under
   labels `torch_tensor_v1` and `ndarray_v1`. Type identity comes from the identifier
   (`orcapod.torch_tensor;{"version":1}`): type, schema and table hashes differ, including
   zero-row and all-null columns. Inside an untyped Python structure the two hash the same
   (label rule 6). State this in `docs/reference/hashing.md` and the PR body.
4. Golden: only `tests/test_hashing/golden/data/torch.json` is added against `main` (26
   entries). Regenerate with `--group torch` only.
5. `pyproject.toml` stays as approved on November 11 (extra `orcapod[torch]`, dev group, uv CPU
   index). Known gaps: CUDA/MPS, torch 2.3 to 2.6.
6. Saved `PipelineJob` load-back: add the tensor test only if #303 is on `main` at merge time;
   otherwise a known gap naming #303.
