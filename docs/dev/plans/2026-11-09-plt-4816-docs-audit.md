# PLT-4816 (part 1): Make the Existing Documentation True — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use sensei:subagent-driven-development (recommended) or sensei:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Python sample in the user-facing docs runs against `main` and shows the output
the code really produces, the docs site builds under `mkdocs build --strict`, and a gap report
tells us what a workshop tutorial still has to cover.

**Architecture:** A pytest module (`tests/test_docs/test_doc_samples.py`) extracts fenced
`python` blocks from the user-facing pages and executes each page as one session (blocks share a
namespace, top to bottom) in a **subprocess** with a throw-away `HOME` and working directory.
For every block it compares what the block prints against the `# ...` comments shown in the
block. A second test in the same directory runs `mkdocs build --strict`. Docs are then fixed
until both are green. No file under `src/` changes.

**Tech stack:** pytest, stdlib only (`re`, `tokenize`, `subprocess`, `contextlib`), mkdocs-material
+ mkdocstrings (already in the `dev` dependency group). No new dependency.

**Linear:** PLT-4816 (part of), ITL-807 (related; the strict extra-column behaviour stays for v0.2).

## File structure

| File | Responsibility |
|---|---|
| `tests/test_docs/__init__.py` | package marker |
| `tests/test_docs/_doc_samples.py` | pure helpers: extract blocks, parse expected output, run a page (also the subprocess entry point) |
| `tests/test_docs/test_doc_samples.py` | unit tests for the helpers + one parametrized test per documentation page |

| `docs/**`, `README.md`, `mkdocs.yml` | fixes |

## Harness contract (what a docs author needs to know)

- Every ```` ```python ```` fence in a tested page is executed. Blocks on one page share one
  namespace and run in order, so a later block may use names from an earlier one.
- A block is skipped only when the line directly above the fence (blank lines allowed) is the
  HTML comment `<!-- docs-test: skip -->` — invisible in the rendered site and on GitHub. Use it
  only for samples that need infrastructure the test run lacks (a Postgres server), never to
  hide a sample that is wrong or merely schematic: make such a sample runnable instead.
- Output check: every non-empty line the block prints must match some comment in that same
  block (the text after `#`, whitespace-collapsed). `...` inside a comment is a wildcard, for
  hashes and other run-dependent values. So a sample that shows `# {'bmi': 1.0}` while the code
  prints `{'bmi': 2.0}` fails. Blocks that print nothing need no comments.
- The page runs with `HOME` and the working directory pointed at a temp directory, so samples
  may write relative paths and `~/.orcapod` without touching the developer's machine.
- Tested pages: `README.md`, `docs/index.md`, `docs/getting-started.md`, `docs/concepts/*.md`,
  `docs/reference/*.md`.

### Task 1: Harness helpers (TDD)

**Files:** create `tests/test_docs/__init__.py`, `tests/test_docs/_doc_samples.py`,
`tests/test_docs/test_doc_samples.py`.

- [ ] **Step 1 — failing unit tests** for the helpers, in `test_doc_samples.py`:
  - `extract_blocks(text)` returns `Block(lineno, source, skip)` for each `python` fence, ignores
    `bash`/untagged fences, handles fences indented inside admonitions (dedents), and sets
    `skip=True` only when preceded by `<!-- docs-test: skip -->`.
  - `expected_patterns(source)` returns comment texts via `tokenize` (a `#` inside a string
    literal is not a comment).
  - `unmatched_output(stdout, source)` returns `[]` when all printed lines are documented,
    returns the offending line when a shown value is wrong, honours `...` wildcards, and
    collapses runs of whitespace (pandas alignment).
  - `run_blocks(blocks)` shares a namespace across blocks, reports an exception with the block's
    line number, and keeps going after a failure.
- [ ] **Step 2 — run, expect ImportError/failures:** `uv run pytest tests/test_docs -q`
- [ ] **Step 3 — implement `_doc_samples.py`** (`extract_blocks`, `expected_patterns`,
  `unmatched_output`, `run_blocks`, and `main(path)` that prints a JSON list of
  `{lineno, status: passed|failed|skipped, error, unmatched}` — used as
  `python -m tests.test_docs._doc_samples <page>` from the repo root).
- [ ] **Step 4 — run, expect unit tests green.**
