# Orcapod Python v0.2 Release Prep (ITL-810) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use sensei:subagent-driven-development (recommended) or sensei:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare everything needed for the developer to publish `orcapod` 0.2.0 through the
GitHub Actions Release workflow, without triggering it.

The release is cut from `main` by `.github/workflows/release.yml`; the version comes from the
git tag via `hatch-vcs`, so nothing in the tree carries a version number to bump.

**Branch:** `eywalker/itl-810-cut-orcapod-python-v02-by-november-1` from `origin/main` (`61d0f18e`).

## Findings that shape the plan (established before writing it)

1. **Patch parity — nothing to port.** `git diff --stat v0.1.2 v0.1.4` touches exactly one
   file, `src/orcapod/core/executors/ray.py`, in `RayExecutor._get_remote_fn`. `v0.1.4`
   builds the remote as `ray.remote(**opts)(wrapper)` when `opts` is truthy and
   `ray.remote(wrapper)` otherwise, inside the cache-miss branch. `main` has the same logic
   as a conditional expression (from `e5efd39b` #233 and `4f7f6fb9` #235):
   `git diff v0.1.4 origin/main -- src/orcapod/core/executors/ray.py` shows only that
   syntactic difference. `main` also has regression tests for the empty-opts path in
   `tests/test_core/test_regression_fixes.py` (the `fake_remote(fn=None, **opts)` tests).
   `v0.1.3` (`dcd54575`) is an intermediate state fully superseded by `v0.1.4` (`16002bc0`).
2. **`v0.1.4`'s commit is on no branch.** `origin/patch` points at `dcd54575` (`v0.1.3`);
   `16002bc0` is reachable only from the tag. Report, do not fix.
3. **`0.1.3` and `0.1.4` were published outside the Release workflow.** PyPI has them;
   TestPyPI stops at `0.1.2`; GitHub Releases stop at `v0.1.2`; no Release workflow run
   exists for them.
4. **The Release workflow has not succeeded since 2026-07-11** (`v0.1.2`). The one later
   attempt (2026-08-20) failed in `Test (Python 3.11)` and was fixed by #254 the same day;
   #254 and #256 then re-pinned every Action. The workflow is untested end to end since.
5. **`CHANGELOG.md` has only an `[Unreleased]` section**, last edited 2026-06-29, whose
   content shipped in `v0.1.1`. Nothing records `v0.1.2`–`v0.1.4`.
6. **Two of the breaking changes the brief names shipped in `v0.1.2`**, not in the 29
   commits since: the `NodeConfig` → `PodConfig` / `NodeConfig` split (#221, ITL-512) and
   the SpikeInterface split (#220, ITL-473). They were never changelogged, so they are
   recorded in the 0.2.0 migration section, labelled as having shipped in 0.1.2.
7. **`pygraphviz` blocks a local `uv sync`** (needs Graphviz C headers, not installed here).
   Coordinator decision: do not install Graphviz; ITL-134 removes the dependency before
   the cut. Run pre-flight with `--no-install-package pygraphviz` and `uv run --no-sync`;
   the unmodified clean install must be re-run after ITL-134 merges.
8. **`Run Tests` is red on `main`** on every commit since at least 2026-08-26, solely
   because the `spiral-integration` job gets `403 Permission table:view denied` from
   SpiralDB. The `test (3.11)` / `test (3.12)` jobs pass. Not part of the Release pre-flight.
