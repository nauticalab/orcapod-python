## `src/orcapod/core/function_pod.py`

### F17 — A function pod stream read again after a partial iteration dropped rows
**Status:** resolved
**Severity:** high
**Issue:** ITL-1039

`FunctionPodStream` keeps one long-lived input iterator, `_cached_input_iterator`, and caches
each output under the index of its input row. `_iter_data_sequential` and
`_iter_data_concurrent` wrapped that iterator in `enumerate()` on every call. The count
restarted at 0 while the input resumed where an earlier iteration had stopped. So after a
partial iteration that consumed `k` rows (a `for` loop with `break`, or `next(iter(stream))`
in a notebook), the next read did three things wrong:

- It took input row `k` as index 0.
- It yielded row 0's cached output for row `k` and dropped row `k`, so `k` rows were lost.
- It cached later rows under the wrong index, which `head()` then showed.

`_CachedFunctionPodStream` inherited the defect. A job's function node keys its rows by entry
id, and a run reads its input in one fresh pass, so job nodes were not affected. Found by the
ITL-1034 code sweep.

**Fix:** the input index is attached once, when the input is first read
(`enumerate(input_stream.iter_data())` in `_ensure_iterator`), and travels with each row. The
sequential path walks indices from 0: it yields a cached index from the cache, and for an
uncached one it pulls, computes and caches the next input row under its own index. The
concurrent path computes the rest of the input, then yields every cached index in order. So
every read, partial, repeated or interleaved, yields every row once, in input order, and each
row is computed once (`tests/test_core/function_pod/test_resumed_iteration.py`). A row whose
function raises is not lost: the sequential path puts it back in front of the input, and the
concurrent path caches every row that returned and keeps the failed ones for the next read,
which computes them again. An input that itself raised mid-read is opened again on the next
read, which skips the rows already cached (both found by CodeRabbit on PR #348).
