## `src/orcapod/pipeline/job.py` — reading a loaded `PipelineJob`

### LJ3 — a job loaded before its user class is registered held the class as text in its source slot
**Status:** resolved
**Severity:** high
**Issue:** ITL-1138

`Pipeline.load` restores a source slot's saved schema with `deserialize_schema`, which keeps the
saved type text (`extension<mod.A@…;…>`) for a column whose extension type the loading process
has not registered: a user class nothing has registered yet (no source of it built, no function
pod naming it defined). The loaded slot then hashed that text, so its pipeline hash differed from
the saved one, and with the bind check of ITL-1112 binding the same source was refused ("declared
extension<…> but the source has A"); a source node names its system-tag columns from the slot's
schema, so an accepted bind would have named them differently from the saving run.

**Fix:** a slot rebuilt from a saved job keeps its saved pipeline hash, and its saved content hash
while unbound, as loaded function and operator nodes do (`SourceNodeBase._keep_saved`). A column
whose type was not restored is kept as pending and restored when a source is bound
(`_restore_pending_types`, called by the bind check), by which time the source has registered the
class; a column still not restorable makes the bind raise `SourceSpecMismatchError` naming the
column and the saved class. Tests: `tests/test_pipeline/test_loaded_slot_unregistered_class.py`.
