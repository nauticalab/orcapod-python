## `src/orcapod/types.py` — `ColumnConfig` (ITL-1067)

### CC1 — `ColumnConfig.handle_config` ignored an `all_info` given inside the config
**Status:** resolved
**Severity:** medium
**Issue:** ITL-1067

`handle_config` expanded `all_info=True` only when it came as the separate keyword.
`columns={"all_info": True}` and `ColumnConfig(all_info=True)` (the docstring's own example) left
every column group off, so `as_table`, `output_schema`, `keys` and `head` returned only the user
columns, with no error.

**Fix:** `handle_config` returns `ColumnConfig.all()` whenever the normalized config has `all_info`
set, so an embedded `all_info` overrides the other fields as the docstring says; a `False` keyword
does not cancel it. Tests: `tests/test_types_column_config_all_info.py`.
