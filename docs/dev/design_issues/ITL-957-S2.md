## `src/orcapod/core/sources/`

### S2 — Default source ids built from a hash did not say what they name
**Status:** resolved
**Severity:** medium
**Issue:** ITL-957

A source id is the source's name: it is stored in every `_tag_source_id::…` value and at the
start of every `_source_<column>` value, and it names the source in a job. When no
`source_id` was given, the in-memory sources (`ArrowTableSource`, `DictSource`, `ListSource`,
`DataFrameSource`) used the bare hex of the Arrow table hash, `000002fe…`: 70 characters that
say neither what kind of source they name nor which algorithm produced them.
`FunctionJobNode.as_source()` and `OperatorJobNode.as_source()` built a third form of their
own, `<node path>:<label>:<hex>`, beside the `DerivedSource` default `derived:<label>:<hex>`.
The config type key of each class (`"dict"`, `"arrow_table"`, …) was written as a literal in
`to_config` and again in the source registry.

The developer decided on November 11, 2026: "if they are going to use some kind of hash value
as their source ID, it ought to have label/prefix to help identify what source type/category
it's associated with."

**Fix:** A default id built from a hash is `<source kind>:<algorithm label>:<hex>`, built only
by `core/sources/source_ids.hash_source_id`, which takes the label from the hash and raises
if the kind or the label is empty or holds a `:` (so the id never contains the `::` of a
source-info value). Each class declares `SOURCE_KIND` once; `to_config`, the source registry
and the default id use it. `SourceStreamBuilder.build` has no bare-hash default any more: it
needs a `source_id` or a `source_kind`. `as_source()` passes no id and takes the
`DerivedSource` default. `hashing.path_n_char` shortens the hex only. A given `source_id` is
never changed.

Left as they are: `PollingSource` (default `str(impl.identity())`, not a hash) and the
sources whose default is a path or a table name.
