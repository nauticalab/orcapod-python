## Cross-cutting

### RN1 — Reserved `_` column names: sources silently drop them, `Pick` / `Index` accept them as new names
**Status:** open
**Severity:** medium
**Issue:** ITL-1165

Columns whose names a stream reads as system columns are handled inconsistently (found on
November 16, 2026 while fixing ITL-1160, probed on that branch):

* `ArrowTableSource` silently drops a data column named `_foo`, `_tag_y`, `_source_y`,
  `_content_hash` or `_context_key`: the source builds without error and `keys()` lists only
  the other data columns.
* `Index(..., out=...)` accepts `_tag_y`, `_source_y` and `_context_key`; `keys()` then lists
  the column but `as_table()` does not have it. `Pick` has the same out-name check (only the
  meta prefix `__` is refused, `schema_utils.require_names_not_meta`).
* ITL-1160 fixed the mappers only: `MapTags`, `MapData` and `MapColumns` refuse, when built, a
  new name that starts with the system-tag prefix (`_tag_`) or the source-info prefix
  (`_source_`), or is the context key column (`_context_key`)
  (`schema_utils.require_names_not_system`).
* Open question: is a bare `_` name reserved at all? A source drops `_foo` and `_content_hash`,
  while `MapData({"x": "_foo"})` and `Index(out="_foo")` give a working data column, and so
  does renaming to `_content_hash`.

To decide: which names are reserved; then a source refuses such a column with an error naming
it instead of dropping it, and `Pick` / `Index` refuse a reserved `out` name through the same
helper as the mappers.
