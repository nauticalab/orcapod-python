## `src/orcapod/logical_types/`

### PH1 — Library value type hashes are provisional until the v0.4 audit
**Status:** in progress
**Severity:** medium
**Issue:** ITL-1068

The value hashes and logical type identifiers of the library value types
(`orcapod.numpy.ndarray`, `orcapod.torch.tensor`, `orcapod.pandas.dataframe`,
`orcapod.pandas.series`, `orcapod.polars.dataframe`, `orcapod.polars.series`) are not yet
guaranteed stable across releases. ITL-1069 audits them for v0.4 against the principle "for
anything maintained or yielded by another system, respect every distinction it has; make no
assumption about what matters semantically". Until then v0.3 warns whenever one is used.

**Fix (interim, ITL-1068):** the types are listed by extension name in `provisional` of
`contexts/logical_types.json`. The logical type registry (`get_by_python_type`,
`get_by_arrow_extension_name`) and the value handler registry (`get_handler`) of each data
context hold that list and issue `orcapod.errors.ProvisionalHashWarning` once per type per
process (`logical_types/provisional.py`). The list enters no hash, identifier or stored path.
The entry is resolved when ITL-1069 settles the hashes and removes the names from the list.
