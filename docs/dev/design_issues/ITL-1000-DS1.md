## `src/orcapod/core/sources/derived_source.py` — identity of a `tags_as_data` source (ITL-1000)

### DS1 — `DerivedSource` `tags_as_data` mapping was not part of the content hash
**Status:** resolved
**Severity:** medium
**Issue:** ITL-1000

A `DerivedSource` with `tags_as_data` hashed `(class name, output schema, source_id)`. Two mappings that give the same schema (two tag columns of one type copied to one name) with one explicit `source_id` shared a content hash, although the copy holds different values.

**Fix:** `DerivedSource.identity_structure` appends `("tags_as_data", sorted items)` when the option is given, as `SpiralDBTableSource` does (ITL-996). The `pipeline_hash` stays schema-only; the plain form is unchanged. Developer decision, November 12, 2026.
