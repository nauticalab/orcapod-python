## `src/orcapod/core/operators/` — Async execution

### O7 — Async system-tag names after a non-source input differed from sync
**Status:** resolved
**Severity:** high
**Issue:** ITL-906

The barrier-mode `async_execute` (`UnaryOperator`, `BinaryOperator`, the default
`StaticOutputOperatorPod.async_execute`, and `Batch`) rebuilt each input from its rows with
`_materialize_to_stream`, an `ArrowTableStream` without a producer whose pipeline hash is the
schema-only hash of a root. `MergeJoin` (system tag rule 2), `Batch` and `GroupBy` (rule 3)
name system-tag columns after their inputs' pipeline hashes, so when an input was an
operator's or a function pod's output the async names, `MergeJoin`'s canonical input order
and every record id derived from them differed from the sync path. The `input_pipeline_hashes`
keyword the operator node passes was ignored. A function node downstream then wrote two sets
of system-tag columns into one pipeline table, and a run on one orchestrator could not extend
a database written by the other (ITL-885).

**Fix:** a barrier path rebuilds each input with `_materialize_input_stream(rows,
pipeline_hash)`, a stream that reports the input's pipeline hash (`_RowsOfStream`).
`input_pipeline_hashes` is a required keyword of every operator's `async_execute`, with no
default and no fallback: the barrier paths and `Join` (whose async path had named system tags
after the input positions `0`, `1`, ... when no hashes were given) raise `ValueError` when the
count does not match the inputs, and the per-row operators and `SemiJoin` take it and do not
use it. `_materialize_to_stream(rows)` only holds output rows. Async names and record ids now equal the sync ones; nothing a
sync run produces moves, and no golden value moves (the golden cases run the sync path).
`tests/test_core/operators/test_async_sync_equivalence.py` runs every operator with an async
path over inputs behind an operator and behind a function pod;
`tests/test_pipeline/test_mixed_orchestrators.py` runs one database with both orchestrators in
both orders.
