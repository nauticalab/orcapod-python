## `src/orcapod/pipeline/node_run.py`

### SC1 — A state-driven run never saw a source whose data changed in place
**Status:** resolved
**Severity:** high
**Issue:** ITL-1102

With ITL-1095 a run holds every node that holds a current run, and staleness comes only from
modified times. A source whose data changes while its object stays the same (a polling
source with new rows, a Delta, SpiralDB, CSV or SQL table that grew) did not move its
modified time before the run judged staleness, so a re-run held every node and never
processed the new data, a behaviour change from v0.2, where every run re-read its sources.
A `PollingSource` also took its modified time from a cursor's `modified_at`, which can be
earlier than a downstream node's last run, and moved it on a fetch that returned no rows.

**Fix:** (developer, November 14, 2026) every run first calls `check_for_new_data()` once on
each source feeding it (`node_run.check_sources`, from `job.run()`, `run_async()` and a job
node's `run()`), before the state rule; a source that finds new data takes it in and moves
its modified time to now. A check that raises warns once (`SourceCheckFailedWarning`), keeps
the source as it was, is listed in `RunSummary.unchecked_sources`, and the run proceeds. A
`PollingSource` polls; its time moves only for a fetch with rows, to the moment it found
them. A `DeltaTableSource` re-reads when its Delta version moved and keeps the new rows
if they changed (order-insensitive); a `SpiralDBTableSource` pins a newer version (metadata
only), unless `asof` was given; a `CSVSource` re-reads when the file's modification time or
size changed; SQL table sources re-read the whole table each run; every re-read compares rows
in any order and moves only when they changed. A `CachedSource` checks its wrapped source and
moves only when the cache will gain rows; a `DerivedSource` follows its origin; a
`SourceProxy` checks its bound source and follows its modified time. Follow-ups: ITL-1103
(revisions per kind), ITL-1104 (positional record ids).
