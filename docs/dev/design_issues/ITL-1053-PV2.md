## `src/orcapod/core/streams/` — notebook preview and `head()`

### PV2 — `head()` refused `sort_by_tags` and showed rows in completion order
**Status:** resolved
**Severity:** medium
**Issue:** ITL-1053

`head()` (ITL-991) was built as "the first rows in stream order": `head_column_config` switched
tag sorting off even under `all_info=True` and raised `ValueError` when `sort_by_tags` was
asked. After an async run a node's stored order is completion order, so its head showed rows
in an order that varied from run to run, and a test asserting that `head(5, all_info=True)`
equals the prefix of `as_table(all_info=True)` failed whenever rows finished out of tag order
(`test_head_keeps_the_tag_arrow_type_of_the_input[async-delta]`, seen on CI; ITL-1001).

**Fix:** developer decision, November 12, 2026: "make it consistent with as_table".
`head_column_config` is removed; `head` takes `as_table`'s column configuration, sorting
included, and applies it to the rows it has, then takes the first `n`. The default stays
unsorted. A node, an `ArrowTableStream`, a computed `FunctionPodStream` and a `DerivedSource`
over a job node shape and sort every row they have (each row keeps its own content hash,
ITL-1029) and slice, so `head(n, cfg) == as_table(cfg).slice(0, n)`. A bounded read
(`SpiralDBTableSource`, a partly computed stream, a polled source's batches) sorts the rows it
has: "the rows read, in tag order", not "the first `n` in tag order". Nothing computes or reads
more than before. When ITL-1002 bounds a node's stored read, a node's sorted head becomes "the
rows read, sorted" unless the database returns rows in tag order.

The notebook preview asks for the tag-sorted head (developer, November 12, 2026: "preview should
sort by tags"; `preview_html`), and its header says "sorted by tags", or for a bounded read
"N rows read, sorted by tags, of about T". Every tag sort goes through
`arrow_utils.sort_by_tag_columns`: tags ascending, nulls last, ties by the system tag columns,
then input order (the node and function pod stream sorts were an unstable Polars sort with nulls
first).
