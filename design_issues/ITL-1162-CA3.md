## `src/orcapod/databases/connector_arrow_database.py`

### CA3 — Connector databases cannot store Orcapod's own stored tables (list, struct and timestamp columns; SpiralDB reserved names)
**Status:** open
**Severity:** high
**Issue:** ITL-1162

A `ConnectorArrowDatabase` over `SQLiteConnector` or `PostgreSQLConnector` cannot store a
function node's result table. Its `__pf_exec_executor_info` and `__pf_exec_extra_info`
columns are `large_list<struct<key, value>>`. The SQLite connector logged "Unsupported Arrow
type ...; mapping to TEXT" and then failed to bind a Python list (`sqlite3.ProgrammingError`)
at commit, after the function had run. The same table's `__pod_ts` (`timestamp[us, tz=UTC]`)
and a side-effect log's `executed_at` were stored as TEXT and read back as `large_string`.
`int8`, `int32` and `float32` columns read back widened, so the second write to the table
failed its schema comparison. PostgreSQL raises for list columns at `CREATE TABLE` and has no
column type for structs, and truncates a column name to 63 bytes, so an operator cache's
system-tag columns (`_tag_source_id::<64-hex>`) read back under other names. Its table names
(the node path joined by `__`, 109-173 characters) are truncated the same way, so two tables
sharing their first 63 bytes would silently be one. SpiralDB refuses value columns named with a `__` prefix and any column
name containing `.`, and drops a timestamp's time zone (ITL-1164), so it cannot hold a function
result table (`__input_data_hash`, ...) or any table's `__data_context`.

**Fix (refusal; developer ruling, November 16, 2026):** each connector states which columns
it stores, in one place (`DBConnectorProtocol.unstorable_column_reason(name, arrow_type,
primary_key=...)`): a column it reads back as written, with the same Arrow type in its large
variant. `ConnectorArrowDatabase.require_storable` raises `UnstorableColumnError` (connector,
column, Arrow type, reason, what to use instead) in `add_records`, before anything is
buffered. A function job node (its result table) and a side-effect job node (its invocation
log) ask the database when it is attached, so a job refuses them before anything runs, naming
the node. An operator job node with a cache and a cached source ask about their bookkeeping
columns (`__node_content_hash`, `__data_context`) when attached or built; their user columns
are checked at the write. `SpiralDBConnector` states its name rule the same way (developer
ruling, November 16, 2026). `PostgreSQLConnector` also states which table names it holds
(`unstorable_table_name_reason`, 63 bytes), checked at every table entry
(`UnstorableTableNameError`). The connectors' silent TEXT fallback in `CREATE TABLE` now
raises.

**Open (the real fix, a later release):** store list and struct columns (for example as JSON
text read back as the same Arrow type) and timestamps on SQLite, and rename SpiralDB's
reserved column names on write and recover them on read, and restore a timestamp's time
zone (ITL-1164); map PostgreSQL column and table names over 63 bytes the same way (ITL-1166), so a function node can
run on a connector database.
