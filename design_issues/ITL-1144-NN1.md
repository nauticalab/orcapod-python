## `src/orcapod/semantic_types/universal_converter.py`

### NN1 — A None inside a container is stored but not read back for a container or a logical type
**Status:** in progress
**Severity:** critical
**Issue:** ITL-1144

A `None` inside a container column (a list or set element, a dict value, a user-class field)
is stored faithfully as an Arrow null, and the in-memory row hash equals the stored row hash.
Reading the stored column back to Python restored it only where the position's type is a
scalar or a user class. A container read as an empty one (`list[set[int] | None]` holding
`[None, {1}]` read `[[], [1]]`; a dataclass field `x: list[int] | None` read `[]`), with a
different row hash; any other logical type failed (`list[UUID | None]`,
`list[Path | None]`, `list[np.ndarray | None]`: `TypeError`). Every read path agreed:
`as_source()`, `DictSource`, a loaded job, a downstream function, and `GroupBy` or `Batch`
over a nullable list, set, `Path` or `UUID` column, where a downstream function received
and stored the wrong value. An in-memory pod-to-pod chain kept the `None`. The decoders
map a null to an empty value (`if value else []`) or hand it to a logical type that does not
accept it.

**Fix (guard, v0.3.0):** `semantic_types/nested_none.py` states which nested None a read
restores. `register_python_class` and the user-class field registration refuse a declared
`X | None` at a nested position whose None cannot be restored
(`NestedNoneNotRestorableError`, naming the column or `Class.field`), and the nested
decoders raise on a stored null there instead of returning a wrong value (Arrow-sourced
columns, whose item nullability the Python type does not show, ITL-1136). A None given for a list,
set or dict whose declared type does not admit one, which the write converters stored as an
empty container, is refused at write (`UnsupportedValueError`, naming the column); an Arrow
map, whose decoder passes a null through, stays readable. Still open: read
these None values back faithfully (a read-side change; storage is already right, so no
stored value or hash moves) and lift the guard. Land ITL-1136's fix only after it: reading
item nullability into the Python type would make every default-nullable nested list read
from Arrow a refused type.
