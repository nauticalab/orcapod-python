## `src/orcapod/core/streams/` — notebook preview and `head()`

### RV1 — No uniform way to compute a stream outside a job
**Status:** resolved
**Severity:** high
**Issue:** ITL-1081

Since ITL-991, `head()` and the notebook preview never compute. But only the operator stream
(`DynamicPodStream.run(*args, **kwargs)`, arguments unused, returning nothing) and the job nodes
had `run()`; a function pod's stream and a source had none, and no protocol declared it. A
user looking at an uncomputed function pod stream had no single call that computes it and
shows the result. The developer ruled (November 13, 2026) that showing must not compute, as
long as there is always a uniform way to trigger the computation, and that it returns the
view object.

**Fix:** `run()` with no arguments on `StreamBase`, `SourceNodeBase` and `StreamProtocol`. It
does the work `as_table()` does and returns a `StreamView` (renamed from `StreamHead`) of
every row. Job nodes keep their `run()` and return the view; side-effect streams deliver on
every `run()` and keep `head()` rowless; blueprint nodes raise what `as_table()` raises.
`DynamicPodStream`'s computation step is the private `_refresh()`. `StreamView.head`, `tail`
and `sort_by_tags` choose what is shown.
