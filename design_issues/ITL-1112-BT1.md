## `src/orcapod/core/nodes/source_node.py`

### BT1 — Binding a source of other column types left every pipeline hash unchanged
**Status:** resolved
**Severity:** high
**Issue:** ITL-1112

`PipelineJob.bind(sources=...)` checked a source against its slot by column names only;
assigning a source node's `bound_source`, and the file sources `PipelineJob.load` rebuilds, were
not checked at all. A source whose `x` is `str`, bound to a slot declaring `x: int`, was
accepted on a fresh and on a loaded job. Every pipeline hash is built from the slot's declared
schema, so none moved, while `output_schema()` passed the bound source through: a downstream
`MapData` reported `y: str` under the pipeline hash of `y: int`. A run then sent `str` values to
a function typed `int` and wrote its rows to the stored paths of the declared types
(`schema:<pipeline hash of y: int>/pdb_v2` and the pod's result table). The same held for a
nullability difference (`int` against `int | None`), which has its own pipeline hash.

**Fix:** `SourceNodeBase.validate` compares, column by column, the source's tag and data schemas
with the declared ones: names, role (tag or data) and Python type, the inputs of the pipeline
hash. A column must have the declared type or, where the slot declares `T | None`, `T`
(developer, November 14, 2026); nothing else fits. Column order and `optional_fields` are not
compared; neither enters the pipeline hash. The `bound_source` setter (which `__init__` now goes
through) calls the same check before it assigns, `bind` checks every source before it changes
anything, its database included, and `load` handles a rebuilt source its slot refuses like one
it could not rebuild. `SourceSpecMismatchError` names the slot, the column and both types and
is now an `InputValidationError` as well as a `ValueError`.

A narrower source is given as the declared schema at one place, `_DeclaredForm`: the same
arrays under nullable fields, and the two system-tag columns renamed from the source's schema
hash to the declared one (their names carry the schema hash). `iter_data`, `async_iter_data`,
`as_table`, `head` and `output_schema` go through it, so the rows equal those of a nullable
source with the same values and source id, row hashes and record ids included, and both append
to one stored table. The node's `content_hash` and source id stay the source's own. The same
form gives a stream's one system-tag pair the slot's names (taken from the stream's own
columns by prefix), so no accepted bind changes a node's path or its columns (names, roles,
types, nullable flags, system-tag names; column order is not part of that, and the form's
declared order is a convenience). Two Arrow types that are one Python type (`int32` and `int64`)
are still not told apart (ITL-949). A source whose system-tag columns are not exactly one
source-id and one record-id column (a joined or merged stream, a raw stream with none) is
refused by the same check (developer, November 14, 2026, ITL-1126; binding one properly is
ITL-1127), also as a pipeline's input: a pipeline built directly over a raw stream is
refused at compile. The slot's own prediction types the record-id system-tag column `bytes`,
as every source's rows have it (it said `str`), so a slot's prediction is the same unbound
and under every accepted bind. No hash, golden value or stored path changed.
