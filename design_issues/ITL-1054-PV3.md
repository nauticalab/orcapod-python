## `src/orcapod/hashing/semantic_hashing/builtin_handlers.py` — pandas value hash identity

### PV3 — pandas values written that storage changed silently or could not read back
**Status:** resolved
**Severity:** high
**Issue:** ITL-1054

A pandas `DataFrame` or `Series` was written whenever pyarrow could convert it, but two kinds of
written value did not come back. First, a MultiIndex whose level names are also level positions
(`names=[1, 0]`; `1.0` and `True` count as `1`) was written with its levels swapped: pyarrow
fetches level `i` with `index.get_level_values(i)`, which pandas resolves as a level name first.
The value read back was another value, nothing raised, and the hash (computed on the restored
form) gave both the same digest. Second, a nested, dictionary, fixed-size or union
`pd.ArrowDtype` column or index level, a `float16` Arrow index level, and a categorical, period,
timedelta, interval, date or `pd.ArrowDtype` column axis, and categories that are tuples, were
written and then failed to read back, and so were a `time64[ns]` index level holding
sub-microsecond values and a MultiIndex level holding tuples or lists. A `False` column label (or Series name) read back as `True`, and an
index level named `__index_level_<n>__` read back unnamed. In a pipeline, the computed result stayed in the result table and could not be loaded on
any rerun. The storage round-trip matrix test hid the second kind: it treated a failed read
like an input storage does not support.

**Fix:** one check, `require_restorable(schema, frame)` in
`orcapod/hashing/pandas_value_hash.py`, shared by `python_to_storage` and the value hash. It
refuses both kinds at write with a `ValueError` naming the column, index level or column-axis
level. A failed read is detected from a zero-row read (`table.slice(0, 0).to_pandas()`, which
keeps the categories), which agreed with the full read on every value tried, on pyarrow 22.0.0,
23.0.1 and 26.0.1, together with a full conversion of each index level and one assembly of a MultiIndex (the
failures found that depend on values). Column labels and index level names are compared as text with those
read back. Future support: tuple categories ITL-1115, `False` labels ITL-1116, sub-microsecond
`time64[ns]` index ITL-1118, generated-looking index names ITL-1119, tuple or list MultiIndex
levels ITL-1120 (which also carries the untested candidates for the v0.4 audit).
`pandas_frame_to_arrow` wraps every Arrow conversion error into `ValueError`, naming the part
that fails. The matrix test now lets only the first write refuse, and it checks each column and
index level by position. The `struct_field_order` ignore option is removed, because it acted
only on the refused struct columns. Identifiers, labels and every golden value are unchanged.
Rows already stored with either kind are left for the migration tool (ITL-1048).
