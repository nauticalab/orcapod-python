## `src/orcapod/core/operators/join.py` — async join keys (ITL-1044)

### AJ1 — Async `Join` could not match list-valued tags and matched the wrong rows on null and NaN keys
**Status:** resolved
**Severity:** medium
**Issue:** ITL-1044, ITL-1050

`Join._binary_streaming_join` indexed rows by `tuple(tag.as_dict()[key])`. A list-valued shared tag (after `GroupBy` or `Batch`) is unhashable, so the async join raised `TypeError`, while the sync join matches such rows. The same code also differed from the sync Polars join on scalar keys: a null key matched another null, and NaN did not match NaN.

**Fix:** the async key is built from the row's Arrow column by `core/operators/match_keys.py`: structs become tuples of their fields, lists become tuples, NaN one shared sentinel, a null of any type means the row never matches, temporal values use their integer storage value (nanoseconds survive). This is the equality measured on the sync join (list order counts, an empty list is not a null list, nulls inside a list or struct are equal, NaN equals NaN, `0.0` equals `-0.0`, a null never matches). A matched shared column also keeps the left tag's values, as the Polars join does. `SemiJoin` shares the same helpers. `MergeJoin`, `GroupBy` and `Batch` async paths are barriers that work on tables and do not hash tag values.
