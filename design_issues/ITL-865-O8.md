## `src/orcapod/core/operators/` — Async execution

### O8 — Async barrier operators raised on an input with no rows
**Status:** resolved (no rows emitted); a typed empty result on async waits for ITL-858
**Severity:** high
**Issue:** ITL-865

The barrier-mode `async_execute` of `UnaryOperator` and `BinaryOperator` (used by
`PolarsFilter`, `GroupBy` and `MergeJoin`) and the default `StaticOutputOperatorPod.async_execute`
rebuilt each input from its rows with `_materialize_to_stream`, which raises
`ValueError: Cannot materialize an empty list of rows into a stream` when a channel delivers
none. The sync path returns an empty stream, so a pipeline with a filter that matches no row
upstream of such an operator completed under the sync orchestrator and failed under the async
one.

**Fix:** a barrier path whose input (any input, for the binary and default paths) delivers no
rows emits no rows and closes its output. That is the sync result of every barrier operator
that exists: an operator never synthesizes a row, and `MergeJoin` is an inner join. The sync
path's typed empty stream needs a schema the channels do not carry, so on async an operator
node that received no rows still reads back columns typed from its Python output schema
(ITL-858, ITL-912). `tests/test_core/operators/test_async_sync_equivalence.py` runs every
operator with an async path with all inputs and with each one input empty;
`tests/test_pipeline/test_operator_node_async_readback.py` runs sync and async jobs with a
filter matching no row upstream of barrier operators and of a function pod.
