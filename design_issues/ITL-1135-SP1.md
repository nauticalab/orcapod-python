## Cross-cutting

### SP1 — DropTagColumns predicted no system-tag columns
**Status:** resolved
**Severity:** low
**Issue:** ITL-1135

Found during ITL-1131. `DropTagColumns.unary_output_schema` kept only the tag-schema keys
that were remaining user tags, so a prediction that asked for system tags
(`columns={"system_tags": True}`, `all_info=True`) left them out, while the computed result
keeps them; `SelectTagColumns` was right. The golden stream summary of `DropTagColumns`
pinned that wrong prediction (`system_tag_columns: []`).

**Fix:** drop only the named user tags from the predicted tag schema. A sweep checks every
operator's prediction against `static_process(...).output_schema(...)` for every column
config, plain stream and job node, with one and two system-tag pairs. It found one more
disagreement, not fixed here: `Batch` and `GroupBy` predict `list[T | None]` for a nullable
data column whose computed table reads as `list[T]` (strict xfail in the sweep): the
Arrow-to-Python reading drops list item nullability (ITL-1136).
