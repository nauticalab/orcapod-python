## `src/orcapod/pipeline/job.py` — reading a loaded `PipelineJob`

### LJ2 — A loaded job dropped its side-effect nodes
**Status:** resolved
**Severity:** high
**Issue:** ITL-1094

A saved job file records each side-effect node (`node_type` `"side_effect"`: label, content
hash, pipeline hash, output schema, node uri, data context, Orcapod configuration), but
`Pipeline.load` had no branch for that node type and skipped it, and so did
`PipelineJob.load`. The loaded job's `nodes` lacked it (`KeyError`); the node below it had
`(None,)` as its upstreams and no edge in the job's graph, though its own hashes, read from
the file, were unchanged; a load-only run (ITL-1095) of a job with a side-effect node above a
function node raised `FunctionNode expects exactly 1 upstream, got 0`; and saving the loaded
job again wrote a file without the node but with its edges. Files written by v0.2.0 have the
same entries and v0.2.0 dropped them the same way.

**Fix:** `orcapod/pipeline/loaded_side_effects.py` restores the node read-only from its
entry: `LoadedSideEffectNode` (blueprint, `Pipeline.load`) and `LoadedSideEffectJobNode`
(`PipelineJob.load`), with the saved label, hashes, schema, node uri, data context and
config, and the restored upstream node as input. Neither has a pod: the file holds no
side-effect function and no pod configuration, so they never deliver and never write the
invocation log. In a load-only run the job node passes its rows on and holds them as
loaded only, through the live `SideEffectJobNode` load-only path, which uses no pod; before
one it reads no rows. `execute`, `async_execute` and `run()` without `load_only` raise
before anything is read. Saving the loaded job writes
the entry back unchanged. The job node's content hash is the saved job's: `PipelineJob.save`
records it in `run.node_job_content_hashes`, as for function nodes, and a file without that
entry gives the descriptor's (blueprint) hash. Nothing stored is keyed by a side-effect
node's content hash; a run's `pipeline_uri`, which hashes its end nodes, now matches the live
job's. No hash value or stored table changes.
