# ITL-1053: head() honours sort_by_tags like as_table

Decision (developer, 2026-11-12): head takes as_table's column configuration, sorting included,
applies it to the rows it has, then takes the first n. Default config stays unsorted.

## Findings (before coding)
- `head_column_config` forced sort off / raised. Replace by `ColumnConfig.handle_config` (no wrapper).
- `FunctionJobNode._head_of_pairs` and `FunctionPodStream.head` sliced BEFORE `_shape_table`; `_shape_table`
  attaches the content hash before sorting (ITL-1029), so for a sorted config: shape all rows, then slice n.
- `ArrowTableStream.head` assembles `limit=n` then sorts: for sorted config assemble all, sort, slice n.
- OperatorJobNode / DerivedSource / SourceProxy / CachedSource / StaticOutputPod delegate to ArrowTableStream.head.
- SpiralDB `_head` reads <= n rows (bounded), `_whole_table` already sorts via as_table: sorts rows read only.
- No store read changes; content hashes for all rows computed only when sort + content_hash asked.
