# ITL-892 Exit Hang Investigation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use sensei:subagent-driven-development (recommended) or sensei:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reproduce and characterise the interpreter-exit hang after a Delta read (ITL-892), evaluate
mitigations with hang rates over at least 40 runs each, and report to the coordinator before any
`src/` or `uv.lock` change.

**Architecture:** One timeout harness (`harness.py`) runs a target script N times as child processes,
counts exits that miss the deadline, and samples the native stack of the first hung child (`sample`
on macOS, `py-spy`/`gdb` not required). Target scripts are small and parameterised by argv so one
harness drives every matrix cell. Version cells run in throwaway environments
(`uv run --no-project --with pyarrow==X --with deltalake==Y`) so `uv.lock` never changes.

**Tech Stack:** Python 3.11/3.12/3.13 (uv-managed), pyarrow, deltalake, polars, Orcapod
`PipelineJob` on `DeltaTableDatabase`, GitHub Actions (temporary, non-required job) for Linux.

Constraints (from the dispatch brief): no change to `uv.lock` or `src/` before the coordinator
approves a mitigation. All experiments live in `superpowers/specs/itl-892-exit-hang/`. Draft PR body
says `Refs ITL-892`.

### Task 12: Percent-encoded table roots (behaviour fix)

`DeltaTable.table_uri` is percent-encoded on every supported deltalake: 1.0.2 and 1.2.1 return
`/x/a%20b/t/`, and 1.6.6 returns `file:///x/a%20b/`. The helper passed it undecoded to
`SubTreeFileSystem`, so a store under `a b`, `pct%` or `é ü` was unreadable. `get_all_records`
swallowed the error, so the store looked empty.

- [x] Failing test first, in `test_delta_native_fs_read.py`: for store roots `a b`, `pct%`,
  `p%20q`, `é ü`, `x#y`, `q?r`, `semi;c` and `plus+` (skip a name the installed deltalake
  itself cannot write), `DeltaTableDatabase.get_all_records` and `DeltaTableSource.as_table()`
  equal the default reader. Assert a correct read, never an empty result. After #290 an
  unreadable table raises `StoreReadError`.
- [x] Fix: `pa_fs.FileSystem.from_uri(uri if "://" in uri else "file://" + uri)`, and use the
  result only when it is a `LocalFileSystem`. Windows drive paths are untested; record a note.
- [x] Fix the troubleshooting snippet the same way.
